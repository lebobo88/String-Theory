# Bringing generated sounds into the repo

The cloud workspace cannot reach ElevenLabs or its asset host; the owner's Chrome (Claude in Chrome tools) can, and it is signed in to GitHub as the repo owner. So sounds travel: ElevenLabs -> a Chrome tab -> a scratch branch (`carrier`) on GitHub -> `git fetch` here. Never upload to `main`. Never open the ElevenLabs flow page in Chrome (it hangs the tab); use the asset host directly.

1. Generate with `mcp__ElevenLabs__creative_generate_in_flow` (`node_type: "sfx"`, `model_id: "eleven_text_to_sound_v3"`, `generations_count: 1`, one flow for the batch from `creative_create_flow`; music: `node_type: "music"`, `model_id: "eleven_music_v2_5"`, say "instrumental, no vocals" in the prompt). Each call costs credits: never repeat a call to retry. Put the length in the prompt ("2 seconds"); the model's floor is about 0.5 s.
2. Get signed URLs with `mcp__ElevenLabs__creative_get_generations` (up to 4 ids per call): `full_res_url` looks like `https://elevenlabsusercontent.com/database/workspace/<ws>/content_generation/<session>/<generation>/content.mp3?Expires=..&KeyName=..&Signature=..`.
3. In Chrome (`tabs_context_mcp {createIfEmpty:true}`, then one `browser_batch`): `navigate` to the first `full_res_url`, then run `fetch.js` (below) with the list filled in. It fetches every file from that same host, packs them (4-byte big-endian length + bytes, in list order), and sends the tab to the GitHub upload page for the `carrier` branch with the pack in the URL fragment. Keep one pack under ~1.3 MB of audio (the fragment must stay under 2 MB); split into several packs if larger, each with its own name.
4. Second call: run `upload.js`. It reads the fragment, puts the file in GitHub's upload form and commits to `carrier`. Check it returns `listed` equal to the pack's name before trusting it. Close the tab when done.
5. Here: `git fetch -q origin carrier && git show FETCH_HEAD:audio/<pack>.bin > /tmp/pack.bin`, then `python3 tools/sound/unpack.py /tmp/pack.bin spec.json` where spec.json is a list, in pack order, of `{"name": "fw_pop", "file": "fw_pop.mp3", "cap": 0.9, "level": false}`. `cap` is the length in seconds to keep; `level: true` evens out loudness inside long sounds whose later beats are quiet (films). It trims the silent lead-in, fades the tail, normalises, writes `audio/<file>` (128 kbps mono; pass `"stereo": true` for music) and prints each sound's loudness shape so you can see that the beats exist.
6. Add each sound to `AUDIO.sfx` in `src/main.js`: `name: ['file.mp3', 'the prompt', volume, 'stand-in existing sound name']`, then `node tools/audio-list.js > audio/PROMPTS.md`.
